## Overview

Container Use implements the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) to provide AI agents with tools for managing containerized development environments. This document details all available MCP tools, their parameters, and usage.

## Connection

To use these tools, agents connect to container-use via stdio:

```bash
container-use stdio [--single-tenant]
```

**Modes:**
- **Multi-tenant (default)**: Multiple sessions, requires `environment_source` and `environment_id` in all requests
- **Single-tenant**: Single session, environment context is tracked automatically

## Tools

### environment_create

Creates a new isolated development environment.

**Parameters:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `environment_source` | string | Yes (multi-tenant) | Path to the Git repository |
| `title` | string | Yes | Short description of work happening in this environment |
| `from_git_ref` | string | No | Git reference to create environment from (default: HEAD). Can be branch name, tag, or SHA |
| `allow_replace` | boolean | No (single-tenant only) | If true, replace existing environment for this session |
| `explanation` | string | No | Detailed explanation of the environment purpose (for logging) |

**Returns:**

```json
{
  "content": [{
    "type": "text",
    "text": "Environment created: fancy-mallard\n\nConfiguration:\n  Base Image: ubuntu:24.04\n  Workdir: /workdir\n  Setup Commands: 0\n  Services: 0\n  Secrets: 0"
  }]
}
```

**Example Usage:**

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "environment_create",
    "arguments": {
      "environment_source": "/path/to/repo",
      "title": "Add login feature",
      "from_git_ref": "main"
    }
  },
  "id": 1
}
```

**Notes:**
- Environment gets a unique ID (e.g., "fancy-mallard")
- Creates a new Git branch: `container-use/fancy-mallard`
- Initializes container from base image with setup commands
- Configuration loaded from `.container-use/environment.json`

### environment_run_cmd

Executes a shell command in the environment.

**Parameters:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `environment_source` | string | Yes (multi-tenant) | Path to the Git repository |
| `environment_id` | string | Yes (multi-tenant) | ID of environment to run command in |
| `command` | string | Yes | Shell command to execute |
| `explanation` | string | No | Description of what the command does (logged in Git notes) |

**Returns:**

```json
{
  "content": [{
    "type": "text",
    "text": "Exit code: 0\n\nStdout:\nHello, World!\n\nStderr:\n"
  }]
}
```

**Example Usage:**

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "environment_run_cmd",
    "arguments": {
      "environment_source": "/path/to/repo",
      "environment_id": "fancy-mallard",
      "command": "python app.py",
      "explanation": "Start the Flask application"
    }
  },
  "id": 1
}
```

**Notes:**
- Commands run in `/workdir` (configurable)
- Environment variables from config are available
- Secrets are injected as environment variables
- Container state is saved after command execution
- Changes automatically committed to environment branch

### environment_file_edit

Applies a line-based patch to edit a file.

**Parameters:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `environment_source` | string | Yes (multi-tenant) | Path to the Git repository |
| `environment_id` | string | Yes (multi-tenant) | ID of environment |
| `path` | string | Yes | Path to file (relative to workdir) |
| `edits` | array | Yes | Array of edit operations |
| `explanation` | string | No | Description of the change |

**Edit Operation:**

```json
{
  "old_text": "line to find",
  "new_text": "replacement text"
}
```

**Returns:**

```json
{
  "content": [{
    "type": "text",
    "text": "File edited: app.py\n1 edit(s) applied successfully"
  }]
}
```

**Example Usage:**

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "environment_file_edit",
    "arguments": {
      "environment_source": "/path/to/repo",
      "environment_id": "fancy-mallard",
      "path": "app.py",
      "edits": [
        {
          "old_text": "DEBUG = False",
          "new_text": "DEBUG = True"
        }
      ],
      "explanation": "Enable debug mode"
    }
  },
  "id": 1
}
```

**Notes:**
- Uses exact string matching
- Each edit must match unique content
- Edits applied sequentially
- Preserves line endings

### environment_add_service

Adds an auxiliary service (database, cache, etc.) to the environment.

**Parameters:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `environment_source` | string | Yes (multi-tenant) | Path to the Git repository |
| `environment_id` | string | Yes (multi-tenant) | ID of environment |
| `name` | string | Yes | Name of service |
| `image` | string | Yes | Docker image for service |
| `command` | string | No | Command to run (default: image default) |
| `ports` | array[int] | No | Ports to expose |
| `envs` | array[string] | No | Environment variables (KEY=VALUE format) |
| `explanation` | string | No | Description of service purpose |

**Returns:**

```json
{
  "content": [{
    "type": "text",
    "text": "Service added: postgres\n\nEndpoints:\n  5432 -> postgres:5432 (environment)\n  5432 -> localhost:54321 (host)\n\nUse 'postgres:5432' to connect from your application"
  }]
}
```

**Example Usage:**

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "environment_add_service",
    "arguments": {
      "environment_source": "/path/to/repo",
      "environment_id": "fancy-mallard",
      "name": "postgres",
      "image": "postgres:16",
      "ports": [5432],
      "envs": [
        "POSTGRES_PASSWORD=secret",
        "POSTGRES_DB=myapp"
      ],
      "explanation": "Add PostgreSQL database"
    }
  },
  "id": 1
}
```

**Notes:**
- Services start automatically
- Accessible via service name as hostname
- Ports mapped to random host ports
- Service state persisted in environment config

## Common Patterns

### Basic Workflow

```json
// 1. Create environment
{"method": "tools/call", "params": {
  "name": "environment_create",
  "arguments": {"environment_source": "/repo", "title": "Add feature"}
}}
// Response: Environment created: fancy-mallard

// 2. Run commands
{"method": "tools/call", "params": {
  "name": "environment_run_cmd",
  "arguments": {
    "environment_id": "fancy-mallard",
    "command": "pip install flask"
  }
}}

// 3. Write code
{"method": "tools/call", "params": {
  "name": "environment_file_write",
  "arguments": {
    "environment_id": "fancy-mallard",
    "path": "app.py",
    "content": "from flask import Flask\napp = Flask(__name__)"
  }
}}

// 4. Checkpoint progress
{"method": "tools/call", "params": {
  "name": "environment_checkpoint",
  "arguments": {
    "environment_id": "fancy-mallard",
    "message": "Initial Flask setup"
  }
}}
```

### Working with Services

```json
// Add database
{"method": "tools/call", "params": {
  "name": "environment_add_service",
  "arguments": {
    "environment_id": "fancy-mallard",
    "name": "postgres",
    "image": "postgres:16",
    "ports": [5432],
    "envs": ["POSTGRES_PASSWORD=secret"]
  }
}}

// Connect from application
{"method": "tools/call", "params": {
  "name": "environment_run_cmd",
  "arguments": {
    "environment_id": "fancy-mallard",
    "command": "psql -h postgres -U postgres -c 'CREATE DATABASE myapp;'"
  }
}}
```

### File Operations

```json
// List files
{"method": "tools/call", "params": {
  "name": "environment_file_list",
  "arguments": {"environment_id": "fancy-mallard", "path": "."}
}}

// Read file
{"method": "tools/call", "params": {
  "name": "environment_file_read",
  "arguments": {"environment_id": "fancy-mallard", "path": "config.py"}
}}

// Edit file
{"method": "tools/call", "params": {
  "name": "environment_file_edit",
  "arguments": {
    "environment_id": "fancy-mallard",
    "path": "config.py",
    "edits": [{"old_text": "DEBUG = False", "new_text": "DEBUG = True"}]
  }
}}
```

## Error Handling

All tools return errors in the standard MCP format:

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "failed to execute command: exit code 1",
    "data": {
      "stdout": "",
      "stderr": "bash: nonexistent: command not found"
    }
  },
  "id": 1
}
```

**Common Error Scenarios:**

- **Environment not found**: `environment_id` doesn't exist
- **Command failed**: Non-zero exit code from shell command
- **File not found**: Reading non-existent file
- **Edit failed**: `old_text` doesn't match file content
- **Service failed**: Service failed to start within timeout

## Single-Tenant Mode

In single-tenant mode, the server tracks the current environment:

```json
// Create sets current environment automatically
{"method": "tools/call", "params": {
  "name": "environment_create",
  "arguments": {"title": "Add feature"}  // No environment_source needed
}}

// Subsequent calls don't need environment_id
{"method": "tools/call", "params": {
  "name": "environment_run_cmd",
  "arguments": {"command": "ls"}  // Uses current environment
}}

// Explicitly switch environments
{"method": "tools/call", "params": {
  "name": "environment_open",
  "arguments": {"environment_id": "other-env"}  // Switches context
}}
```

**Benefits:**
- Simpler API for single-session agents
- Natural conversation flow
- Automatic environment tracking

## Best Practices

### For Agent Developers

1. **Always checkpoint after significant work** - Creates recovery points
2. **Use meaningful titles and explanations** - Helps humans review work
3. **Prefer `environment_file_edit` over `write`** - Preserves other file content
4. **Check return codes** - Don't assume commands succeeded
5. **Use services for dependencies** - Don't install on base image

### For Tool Implementation

1. **Validate inputs** - Check required parameters
2. **Provide helpful error messages** - Include context and suggestions
3. **Log operations** - Use `explanation` parameter
4. **Save state after changes** - Call `repository.Update()`
5. **Handle cleanup** - Close resources, clean temp files
